# Portable evidence transformation

The original captures remain private and unchanged. `TRANSFORM-MAPPING.json`
records every selected raw file's SHA-256, its published path and published
SHA-256. `raw-sha256.txt` lists raw capture hashes; `sha256.txt` covers all
published files except itself. Neither manifest claims the two byte forms are
identical.

The export uses the installed `redact_tree`, `portable`, `portable_command` and
`path_token` helpers, followed by explicit observed-selector replacements.
Kubeconfig and execution-host paths, the private cluster context, API server,
access identity, existing namespace, PVC and NFS access route receive stable
SHA-256 tokens. Tokens use the first twelve hexadecimal characters. Matching
source values receive matching tokens. In-cluster test artifact paths remain
visible so the requested destination can be compared with actual read-back and
exact cleanup. Public image digests and the supplied test MACs remain visible. Plan and input
digests still identify the original inputs, not the tokenized publication.

Operation results, error reasons, callback order, run IDs, resource UIDs,
package and functional hashes, content digests, sizes, timestamps, native exit
codes and trace event counts are retained. JSON serialization is normalized;
JSON Lines event order is unchanged. No success result or missing provider
observation is generated by this transformation. `measurement.json` retains
the separately captured timing report derived
from these traces and the cleanup observations; it is not a performance
comparison. The storage harness report
is identified separately from installed command receipts.

The export excludes broad cluster inventories and credential-bearing files.
The earlier rejected-plan note was reconstructed from task-summary output,
so it is excluded from the evidence mapping. The README identifies the harness
correction without presenting the reconstruction as a captured receipt.
