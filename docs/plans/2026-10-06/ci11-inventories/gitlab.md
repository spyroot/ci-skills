## Port notes
**Cross-cutting**
- **One transport.** Use GlabAPIClient (ci-skills/lib/core/gitlab_api.py:262-296). It puts JSON bodies in a 0600 temp file, never argv (:263-268).
  - The source has three transports, even though it calls source_gitlab_api the only one ($SOURCE_REPO/automation/lib/access/gitlab_auth.bash:192-194):
    - glab through that function;
    - curl at $SOURCE_REPO/automation/lib/ci/pipeline.bash:62-76, which puts the token on argv (:72) while the comment at :60-61 claims it does not;
    - curl at $SOURCE_REPO/automation/lib/access/gitlab_mcp.bash:127.
  - It also uses `glab repo list` and `glab runner assign` and decides success by matching their output text ($SOURCE_REPO/automation/lib/access/gitlab_runners.bash:48-51, :66-72).
  - ci-skills itself has a second path: glab_argv, _read_json and run_command_tail in collect_gitlab_job (ci-skills/lib/core/collect.py:798, :822, :853).
  - Decision needed for LOGS: the trace endpoint returns text, and GlabAPIClient exposes only `*_json` methods (gitlab_api.py:283-294). Either add a text method or reuse collect's trace read. _request internals were not verified from headers.
- **One envelope.** Emit through ci-skills report/emit (collect.py:23; ci-skills/lib/core/gitlab_actions.py:22). Never emit gitlab-access-result-v1 or the GitLab*Result kinds (gitlab_auth.bash:20; $SOURCE_REPO/tests/gitlab_util.bats:909-913). Status mapping:
  - READY → PASS.
  - WOULD_CHANGE → DRY_RUN for an offline plan, or PLANNED for a live read-only plan (ci-skills/lib/core/catalog.py:541-548).
  - AUTH_FAILED, VERIFY_FAILED, INVALID_FORMAT, MISSING_* and TOOL_MISSING → BLOCKED, keeping the class as the reason.
  - A write whose result was lost → PARTIAL via unverified_write (gitlab_api.py:57-70). The source wraps the pipeline POST in `timeout` ($SOURCE_REPO/automation/lib/access/gitlab_pipeline.bash:56-63) and loses that case today.
- **Exit codes.** The source uses 0, 1, 2, 64-67, TIMEOUT, 69 and 129-143 ($SOURCE_REPO/scripts/utility/gitlab_auth.sh:65-67; $SOURCE_REPO/scripts/utility/gitlab_mcp.sh:51-53; gitlab_util.sh:13; $SOURCE_REPO/scripts/ci/cluster-access.sh:36-37). ci-skills declares only 0 and 2 (catalog.py:550-553). Collapse every non-zero code to 2 and keep the class as a typed reason.
- **`--dry-run` conflict.** The source's `--dry-run` on a component delete mixes two things:
  - a live read-only plan: exact head (gitlab_util.sh:1637-1650) and the profile and namespace reads (:1573, :1579);
  - a pipeline write: the preview pipeline is POSTed (:1586-1607, :1764-1765, :322-323; tested at gitlab_util.bats:611-628).

  ci-skills `--dry-run` never contacts any API (catalog.py:36). The preview cannot be PLANNED either, because PLANNED means "no resource mutation" (catalog.py:546) and `--live-plan` means "without writes" (:346). The pipeline is the mutation; the cluster being untouched (gitlab_util.sh:256-258) does not change GitLab's state. The port separates the two:
  - a pipeline-start kind with `--live-plan` for the reads only, whose digest covers the resolved sha (gitlab_actions.py:48-65, :616-620);
  - `--apply --confirm-plan` for the POST (gitlab_actions.py:527, :547-548, :633-634).
