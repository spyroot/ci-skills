## Port notes

- **Cross-cutting contract (applies to every port)**
  - **`--dry-run` means something different.** In the source, the default plan or `--dry-run` reads the cluster live: nic-mtu.sh:19-23, csr-approve.sh:20-21, node-status.sh:16, serve-iso.sh:25-26 with :80-82, node-image.sh:119, get-rhcos-iso.sh:67. In ci-skills, `--dry-run` must not contact any API (ci-skills/tools.json:860). So the source's live read-only plan becomes the default run with status `PLANNED` (tools.json:828), and `--dry-run` only lists the probes.
  - **Exit codes collapse.** The source uses 0, 1, 2, 64, 65, 66, 67, 129, 130 and 143 (serve-node-iso.sh:104-108; nic-mtu.sh:45-47). ci-skills has only 0 and 2 (tools.json:785-788). Source 1 (unhealthy or failed) maps to `PARTIAL` or `BLOCKED` with exit 2. Source 64-67 (usage, data, missing file, missing value) map to exit 2 as an unusable input. For signals, reuse `Interrupted` and `_signal_interrupt` (ci-skills/lib/core/mtu_consistency.py:43, :551).
  - **Mutating commands** use `--apply --confirm-plan`, as in tools.json:416-418 and :708-711. They set `read_only: false` and name their side effects (tools.json:727, :739). Register every new command in tools.json `commands` and `routing` (:802-820) and through catalog (ci-skills/lib/core/catalog.py:562 missing_required_options, :577 options_for, :587 describe, :616 describe_node, :642 manifest).
  - **Every oc or kubectl call** should go through `runtime.run_command_bounded`. The operator named it; lib/core/runtime.py exists in the directory listing, but its contents were not read. It replaces the source's two-timer bound (k8s_state_observer.bash:104, :224-302).
  - **target.toml entries below are proposals.** target.py was not read, and the target lookup order is tools.json:831-856.
